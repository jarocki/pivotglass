# Release history and qualification records

Each version directory preserves dated release notes, QA receipts, editorial
findings, and handoffs. A historical test count or screenshot describes its
checkpoint; it is not current qualification evidence. Use the
[current Quick Start](../QUICKSTART.md) for executable installation commands and
[GitHub Releases](https://github.com/jarocki/pivotglass/releases) for public status.

## v0.9.9 — current candidate

- [Qualification checkpoint](v0.9.9/QA.md): actual completed checks and the open natural-voice/publication gates.

- [Completion matrix](v0.9.9/COMPLETION_MATRIX.md): every original v0.9.8/v0.9.9
  request, its delivered artifact, and remaining qualification/publication gates.
- [Expert editorial and operations review](v0.9.9/EXPERT_EDITORIAL_REVIEW.md): contract checks, documentary recovery rehearsal, and coverage inventory.
- [Newcomer editorial review](v0.9.9/NEWCOMER_REVIEW.md): artifact-backed clarity and executable-workflow corrections.
- [Completion plan](../plans/V0.9.9_COMPLETION_PLAN.md): owner correction, ordered
  acceptance gates, and the difference between repository copy and external publication.
- [Current documentation paths](../README.md): user, analysis, marketing, and operations guides.
- [Current demo transcript](../media/pivotglass-guided-demo-transcript-v0.9.9.md):
  actual synthetic workflow, narration, chapter times, and recording-method disclosure.
- [Release trust](../RELEASE_TRUST.md): immutable build, media checks, owner signature,
  public download, and version/commit reconciliation.

Candidate artifacts and passing local checks do not establish public release.
The release is complete only after public main, matching tag, GitHub Release,
artifacts, signature, and downloaded readback have been verified.

## Earlier records and future gate

Earlier version directories retain their QA and handoff records. Retired
executable/package names use labeled historical placeholders. Plans record
intent rather than verification.

The [release roadmap](../plans/V0.9.8_TO_1.0_ROADMAP.md) retains a separate final
correctness, resilience, efficiency, security, and usability pass. Owner approval
of that review is required before assigning or publishing v1.0.0. Approval of
v0.9.9 does not imply approval of v1.0.0.
