# Adversary Pursuit v0.6.0 implementation plan

**Status:** initial reviewed plan
**Target:** the final pre-1.0 capability release
**Theme:** put every operational state in the cockpit, turn stored evidence into
an editable investigation graph, and remove the remaining mechanics that break
analyst flow.

## Product boundaries

- Pivotglass remains the primary AI-augmented cockpit; `ap tui` remains the
  keyboard-first equivalent and `ap basic` remains direct control.
- Deterministic code and direct APIs own state, evidence collection, chart
  selection for known data shapes, and integration transforms. A model may
  explain or propose, but it may not invent telemetry, relationships, or
  successful actions.
- Evidence, inference, decorative character voice, music, game state, and
  product diagnostics remain visibly distinct.
- API keys are secrets. The browser may edit masked values through a local
  service, but raw secrets never enter logs, exports, DOM attributes, analytics,
  or model prompts.
- Existing workspaces, historical character identifiers, STIX objects,
  annotations, and exports migrate forward without destructive rewriting.

## Research applied

- [Microsoft Flint](https://microsoft.github.io/flint-chart/) compiles concise
  semantic specifications into backend-specific charts and derives layout
  geometry. AP should send it data, semantic types, chart intent, encodings,
  and available size—not hand-maintained Chart.js geometry.
- [From Data to Viz](https://www.data-to-viz.com/) organizes chart choice by
  data shape and warns about bin sensitivity, overplotting, unreadable
  multi-series lines, rainbow scales, and radar-chart comparison limits.
- [VirusTotal Graph](https://docs.virustotal.com/docs/graph-documentation)
  treats files, URLs, domains, IPs, and relationships as explorable entities.
  Its node guidance supports labels, manual links, pinning, expansion state,
  directional relations, selection context, and CSV extraction.
- The supplied
  [technical chart guide](https://www.geeksforgeeks.org/data-visualization/choosing-the-right-chart-type-a-technical-guide/)
  and [Information is Beautiful](https://informationisbeautiful.net/) reinforce
  that a visualization must answer an analyst question, not merely decorate a
  dashboard.
- Integration planning uses the upstream descriptions of
  [SCOT](https://github.com/sandialabs/scot),
  [go-roast](https://github.com/jarocki/go-roast),
  [nucleotide](https://github.com/jarocki/nucleotide), and
  [Vertex Synapse](https://github.com/vertexproject/synapse).

## W-060-01 — Cockpit terminal and diagnostics

Move every user-relevant status and error emitted by the Pivotglass launch
process into a shared diagnostics event stream.

Deliverables:

- a scrolling **Activity & Errors** terminal in Pivotglass with timestamps,
  severity, component, human-readable summary, and next action;
- a bounded local event envelope shared by stderr logging and the web adapter;
- clickable log references that open a sanitized detail dialog for the exact
  error and file location without allowing arbitrary file reads;
- copy, filter, clear-view, pause-follow, and download-sanitized-log controls;
- automatic focus only for critical errors; routine events must not steal input;
- no secret values, authorization headers, full query strings, or private file
  contents in browser payloads.

Acceptance:

- normal launch, module start/result, missing key, API timeout, malformed
  response, and internal exception each appear in the web terminal;
- the console never claims a probe succeeded before its authoritative event;
- a log link can resolve only files in the approved AP log directory;
- terminal launch output contains only the address and truly pre-browser
  failures.

## W-060-02 — Semantic visualization authority

Create one Python-owned visualization-intent envelope and one TypeScript
Flint-spec adapter. Flint 0.3.x remains the compilation authority; Chart.js,
ECharts, or Vega-Lite are renderer choices behind it.

The deterministic selection policy begins with the analyst question:

| Question | Required data | Default view | Guardrail |
| --- | --- | --- | --- |
| When was activity concentrated? | timestamp + count | calendar heatmap | expose timezone and missing days |
| How complete is this one dossier? | bounded facet scores | radar + accessible table | one dossier; common 0–100 scale |
| How are values distributed? | one numeric field | histogram | show count and adjustable bins |
| Which entities relate? | nodes + typed edges | relationship graph | no edge without provenance |
| How does a hierarchy divide? | parent/child links | dendrogram or sunburst | preserve path and depth |
| Are numeric features correlated? | 2+ normalized measures | scatter/PCA projection | label explained variance; expose points |
| Which indicator/probe work is pending? | indicators × probes | task matrix heatmap | non-color status marks |
| How does a metric change? | ordered time + value | line/area | avoid unreadable multi-series “spaghetti” |

Model involvement is optional: an AI may propose a Flint intent when no standard
policy matches, but the proposal must validate against an allow-listed schema
and the analyst sees the question, fields, transform, and caveats before render.

Acceptance:

- every visual includes a plain-language question, source scope, accessible
  data table, empty/error state, and export of the exact plotted data;
- charts never infer missing values silently;
- high contrast, Day/Night themes, keyboard navigation, and reduced motion work
  across renderer backends;
- visual QA covers narrow, laptop, and full-screen views.

## W-060-03 — Editable relationship workspace

Build an in-browser graph on AP's persisted STIX relationship authority.

Deliverables:

- actual indicator values as labels; backend IDs remain detail-only;
- typed, directional edges with provenance, first/last seen, confidence source,
  and manual-vs-observed distinction;
- expand, collapse, pin, drag, multi-select, center, undo, redo, annotate,
  relabel, add manual node/link, and delete-manual-item actions;
- click to open evidence detail; double-click to expand known relationships;
- filters by entity type, relation, source, time, verdict, and confidence;
- saved layouts separated from evidence so moving a node never alters truth;
- GEXF/STIX/JSON/CSV export and Gephi compatibility.

Manual relationships are analyst assertions, never observed facts. They require
an annotation and retain author/time provenance.

## W-060-04 — Task matrix

Evolve Task Constellation into a virtualized matrix with indicators on the Y
axis and probes on the X axis. Each cell represents one authoritative job
lifecycle and opens its full event/evidence history.

Acceptance:

- all queued, running, completed, failed, skipped, and canceled jobs are
  visible without losing order;
- sticky row/column labels, keyboard traversal, row/column filtering, and a
  visible legend work at 320 px and large datasets;
- literal 3×3-pixel LEDs may summarize cells at dense zoom, but text/non-color
  state remains available;
- no duplicate cards are created for a single job.

## W-060-05 — Configuration center

Add a local **Configuration** dialog for models and intelligence plugins.

- list every supported provider/service with configured, missing, or invalid
  state;
- reveal a secret only after an explicit local action, keep it masked by
  default, and never return it during ordinary state polling;
- edit, remove, and test one credential without restarting;
- separate “credential accepted” from “provider has quota/access” and show the
  exact tested endpoint and time;
- offer environment-owned credentials as read-only without copying them into
  configuration;
- keep `model select` and terminal configuration commands behaviorally equal.

## W-060-06 — Focus, overlays, terminology, and help

Close the focus defect with an explicit focus-state machine rather than ad hoc
blur handlers. Escape closes the top overlay; closing or completing an overlay
restores the opener; no invisible element retains keystrokes.

All dialogs—including Help, Full History, Artifact Field, Evidence Details, and
alerts—use a fixed viewport portal and fit inside the current viewport. They
must never be positioned relative to document height.

“Master Caution” currently means an aggregate of conditions needing operator
attention. Rename it **Attention Needed**, then label each item as Error,
Warning, Missing Configuration, or Action Required. Review every visible name,
acronym, abbreviation, and command with junior-analyst comprehension tests;
retain specialist terms only where they are the domain-standard label and add a
plain explanation.

Graduated help:

1. **Novice** — task wizard, progressive tooltips, checkpoints, and reversible
   “show me” actions.
2. **Adept** — no persistent wizard; delayed contextual tips and a **Show me**
   path when repeated errors, stalled focus, or help requests indicate need.
3. **Expert** — terse labels, keyboard-first operation, minimal animation, and
   no unsolicited instruction.

The selected level is local, reversible at any time, and never inferred from
analytical performance.

## W-060-07 — Dossier decahedron

Render the nine current evidence facets on a keyboard-operable rotating
decahedron. The tenth face is **Overview**, not a fabricated evidence dimension.

- drag, arrow keys, or a visible facet list rotates selection;
- Enter/click opens detail in a viewport-centered panel;
- face color/texture communicates completeness with redundant text and shape;
- reduced-motion mode replaces rotation with an instant facet transition;
- the accessible list and flat radar/table view remain first-class alternatives;
- 3D state is presentation-only and never owns dossier data.

## W-060-08 — Visual atmosphere and focus-safe motion

Replace the current hard scan line with a broad, soft-edged, low-opacity fog
band based on the visual treatment of [jarocki.org](https://jarocki.org/).
Implement it with gradients and blur, pause it under reduced motion, and keep it
behind all content and focus indicators.

No character animation or mini-game may capture typing, cover evidence, change
investigation state, or continue consuming significant resources while hidden.

## W-060-09 — Integration architecture

All integrations begin as optional adapters behind stable AP contracts.

### SCOT

Map SCOT alerts/events, entities, tags, comments, and analyst knowledge into a
versioned exchange envelope. Begin read-only, preserve remote IDs and links,
and require an explicit preview before any write-back. Test pagination,
conflicts, permissions, and round-trip provenance against a disposable SCOT
instance.

### go-roast

Prefer its deterministic JSON/NDJSON CLI or library boundary to decode and
analyze Interactsh OAST domains. Store decoded timestamp, machine ID, PID,
counter, campaign, classification, confidence, and caveats as sourced
properties and typed relationships. Do not treat spoofable machine IDs or
timezone estimates as identity proof.

### nucleotide

Consume its documented JSONL/library formats for URL-to-template attribution,
observability-tier rules, and actor-behavior fingerprint YAML. Record matched
template, ambiguity, tier, extracted behavior, and tool-version provenance.
Generated Snort/Suricata/Sigma content is an artifact for review, never an
automatically deployed control.

### Vertex Synapse

Build a mapping spike between AP STIX objects/relationships and Synapse
forms/properties/edges. Preserve normalized indicator values, source-specific
properties, time semantics, and provenance. Storm queries remain opt-in remote
operations with budgets and cancellation. Synapse may become a graph backend;
it must not create a second, drifting relationship policy inside AP.

## Delivery sequence

1. Diagnostics envelope, Activity & Errors terminal, focus state machine.
2. Visualization intent schema, Flint compiler adapter, task matrix.
3. Relationship workspace and saved presentation state.
4. Configuration center and graduated help.
5. Dossier decahedron and fog atmosphere.
6. Read-only integration spikes, schemas, fixtures, and threat models.
7. Write-back proposals only after round-trip evidence and explicit approval.

## Release gates

- full Python, TypeScript, static build, dependency, and supply-chain checks;
- real PTY tests for Up/Down, Page Up/Down, wheel, scrollbar click/drag, new
  output while reading history, and exact Back/Escape restoration;
- browser interaction QA at 320 px, 1024 px, and desktop for every overlay,
  help level, focus route, theme, and reduced-motion mode;
- no horizontal document overflow and no tooltip/dialog clipping;
- secret-redaction tests and attempted log-path traversal tests;
- seeded graph/task/visualization fixtures with exact evidence/provenance checks;
- screen-reader and keyboard-only walkthrough by a junior and expert analyst;
- listening QA for every character with music off/on and rapid theme changes;
- documentation, help, executable behavior, version, and migration parity.
