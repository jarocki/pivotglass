# v1.4.0 plan: enrichment that tells the story

Filed 2026-11-21 from owner direction after hands-on use of v1.3.0. Branch:
`feature/v1.4.0-enrichment-and-focus`.

## Purpose

Pivotglass exists to focus analysis and remove friction. Enrichment should add
context and relationships that explain an indicator's role, recognise related
indicators that are *not* malicious so the analyst can set them aside, and let
the configured AI propose hypotheses as the evidence accumulates: the Dossier's
"puzzle pieces" resolving into a picture of the attack, campaign, or actor.
Evidence stays distinguishable from inference throughout.

## Owner decisions (2026-11-21)

| Question | Decision |
|---|---|
| IP geolocation source | Local databases only (DB-IP Lite country/city + ASN, CC BY 4.0, keyless, monthly). No case IP leaves the machine for geolocation. |
| Known-good recognition | Bundled MISP warninglists subset (CC0, offline) **and** CIRCL hashlookup (online, NSRL-backed). A match is context ("known"), never a verdict. |
| AI hypotheses | Propose, analyst accepts. Proposals cite evidence ids, are labelled inference, and enter the Dossier only on acceptance. |

## Work items

1. **Editable API base URLs.** Every AI provider and enrichment service shows
   its default base URL in Configuration and accepts an override (API gateway,
   proxy). One authority: the service registry holds the default; config holds
   only an override; request URLs and model-list URLs derive from the effective
   base. Overrides are validated (https, or http only for loopback).
2. **AI provider registry refresh.** Replace retired model ids
   (`claude-3-5-sonnet-20241022`, `gemini-2.0-flash-exp`, `qwen2.5:8b`), bump
   litellm (1.84.0 predates current models), add Azure OpenAI, a generic
   OpenAI-compatible endpoint, and a local OpenAI-compatible endpoint (LM Studio,
   mlx_lm, llama-server). Keep Ollama as the default local runtime; default local
   model `qwen3.6:35b`, fallback `qwen3.5:9b` for 16 GB machines. Warn that the
   Gemini free tier trains on prompts. Source: research notes, 2026-11-21.
3. **Geolocation and ASN for every IP** from local DB-IP Lite databases, with
   attribution, a refresh command, and small flag emoji wherever IPs appear.
   Country is infrastructure location, not actor origin.
4. **Known-good recognition.** Offline MISP warninglist subset (public
   resolvers, cloud/CDN ranges, Tranco top sites, empty and known OS hashes,
   sinkholes, security scanners) plus CIRCL hashlookup for hashes. Matching
   indicators are marked "known: <list>" and can be set aside in one action.
5. **New context sources** (keyless first): Mnemonic passive DNS, Shodan
   InternetDB, SANS ISC, RDAP, Wayback CDX; Pulsedive with a key. GreyNoise
   moves off the deprecated `/v3/community` when a free-tier path is confirmed.
6. **AI hypotheses and puzzle pieces.** After each enrichment wave the
   configured AI receives the evidence neighbourhood (ids, values, sources,
   known-good marks) and returns structured proposals: hypothesis, supporting
   and contradicting evidence ids, missing pieces to check next. Proposals are
   shown in the Dossier as inference; acceptance records the analyst's decision.

Each item ships with tests, docs, and a changelog entry; v1.4.0 is a minor
release.
