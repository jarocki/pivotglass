# v1.3.0 / v1.4.0 Plan — Indicator Focus, Details on Demand, Real Pivots

Filed 2026-11-15. Source: owner direction after a hands-on evaluation of v1.2.0.

## Purpose

The analyst's goal is to understand how indicators relate to each other, how
they can reveal more infrastructure, and where they sit in an attack path.
v1.2.0 makes that slow: document intake lives in nested collapsible panels,
the preview is a plain `<pre>`, relations are invisible during review, PDFs
yield no indicators, and a keyless install cannot resolve a domain.

Design rule for this cycle: **form follows function, details on demand, low
friction.** Every visible element must help the analyst decide something.
Explanatory or brand copy that does not change a decision is removed.

## Workstreams

### v1.3.0 — Indicator focus (the main work)

1. **Indicator focus mode.** (#12) Full-viewport split view: indicator list on the
   left, rendered source on the right. The focused indicator is highlighted and
   scrolled into view; every other candidate is lightly marked. Keyboard first:
   `j/k` or arrows move focus, `space` toggles selection, `a` admits the
   selection, `t` tags, `/` filters, `esc` exits. Works for a fresh preview and
   for any stored library document. Replaces the nested candidate panels.
2. **Safe rendered preview.** (#13) One server-side render authority produces a
   sanitized HTML rendering for text, Markdown, HTML, email, CSV and JSON. PDF
   renders client-side with pdf.js (scripting and eval disabled). Highlight
   anchoring uses the candidate's occurrence ordinal of its raw value in the
   parser text; when a rendered view cannot locate it, the UI says so and the
   exact extracted-text view remains available. Hostile-content rules: no
   scripts, no event handlers, no remote fetches (images, fonts, CSS), links
   inert, rendered inside a `sandbox` iframe without `allow-scripts`.
   *Contract change:* v1.2.0 said raw source bytes never enter the DOM after
   ingestion. Sanitized derived HTML will; PDF bytes reach pdf.js's canvas.
   DATA_SAFETY.md must state the new boundary.
3. **PDF text extraction.** (#14) Bounded `pypdf` extraction with page markers so
   candidates get real offsets.
4. **Details on demand.** (#15) Hovering (or focusing) any indicator, in the list or
   in the rendered source, shows a translucent popover. Contents, each labelled
   by basis:
   - *Workspace:* known entity, relationships with their basis, investigations,
     tags.
   - *Other sources:* other documents in this workspace that contain the value.
   - *This document:* structural derivation (URL → domain/IP, email → domain,
     refang) and co-occurrence in the same line or paragraph, explicitly
     labelled as position, not an asserted relationship.
   Backed by one indicator-context endpoint, so the list, the source view and
   the graph share an authority.
5. **Multidimensional tagging.** (#16) An indicator tag authority keyed by
   `(entity_type, normalized_value)`, so tags apply before and after admission.
   Each tag is `dimension:value` with author, time and optional note. Default
   dimensions are `role` (c2, delivery, staging, exfil, phishing, hosting,
   benign), `tactic` (ATT&CK enterprise tactics in kill-chain order, which
   gives the attack-path ordering), `cluster` (free text) and `status`
   (reviewed, false-positive, needs-pivot). The focus list can group by or
   filter on any dimension. Tags project into the graph and exports. Analyst
   promotion groups remain batch provenance, a separate concept.
6. **Low-friction intake.** (#17) Drop, paste or choose a file; preview starts
   immediately. Paste plain text or a list of indicators without making a file.
   One action ingests and admits. Receipts collapse to one status line with
   details on demand.
7. **Copy and polish.** (#18) Remove marketing copy from the work surface. Fix every
   defect in the findings table except the ones scheduled for v1.4.0.

### v1.4.0 — Real pivots

8. **`pivotglass config` CLI** (#19) (`set`, `check`, `show`), which makes the
   remediation text true.
9. **abuse.ch Auth-Key** (#20) for ThreatFox, URLhaus and MalwareBazaar, with
   not-configured reported as not-configured.
10. **Keyless infrastructure pivots.** (#21) DNS (A, AAAA, NS, MX, TXT, CNAME), RDAP
    registration with nameservers and registrar as pivotable observations,
    IP → ASN / prefix.
11. **Bounded multi-hop pivoting.** (#22) One pivot authority in
    `modules/pivoting/`, used by the web, the REPL and the cyberdeck: depth and
    request budget set by the analyst, honoring stop, skip, focus and add,
    gated by the existing `pivot_policy`.

## Release discipline
